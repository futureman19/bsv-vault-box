# Kenya v1 — Rift Escarpment & Soda Lakes

Open `kenya-v1.html` directly in Edge/Chrome, offline. Entire viewer: **3,086,224 bytes**. Standalone `kenya.glb`: **1,764,820 bytes**. Drag/touch rotation, staged Open/Close, Reset, reduced motion and real-render fallback are embedded. No runtime downloads, wallet, mint, node, chain queries or deployment.

## Art and provenance
Original script-authored Blender landscape interpretation of the Kenya Lake System; research and pre-model contract are in `design-brief.md`. Three discrete blue-green lake inlays sit between low ochre escarpments on a warm volcanic-stone-inspired box. This is not a map, traditional craft replica, photographic scan or representation of every Kenyan culture. Geometry and compact maps are procedural. The included `mechanism.blend` is the inherited Japan pilot mechanical base, not its cedar/tree art. Three.js license is included.

`kenya.blend` is editable packed source; `author.py` regenerates geometry/export and the actual source-rendered `poster.png`. Maps are in `maps/` and generated by `maps.py`. Poster is not AI promotional artwork. The original attempt was interrupted after art and tests; this recovery independently rebuilt and reran the gates before packaging.

## Verified
- Independent saved-source reopen: 24 moving and 59 static meshes; all 81 staged poses have zero unintended moving/static or latch/lid surface intersections. Only named mating bearing pairs are excluded. Hollow-floor ray hits z=0.2650000155; ten physical hinge attachment overlap pairs pass.
- Bidirectional source/export maximum nearest-vertex error: 1.712013073529306e-7, below 1e-5. Three packed source maps present.
- Motion tests: exact 80-degree latch release before 105-degree lid opening; 81 samples and invalid-input negatives.
- Actual GLTFLoader: finite vertices and zero degenerate triangles. Three distinct lake meshes and all terrain/shore/lake parentage pass. Terrain maximum height 2.4665117264; two decoded 512-square color maps have range 62. Real runtime removal of one lake fails the three-lake assertion.
- Offline file:// Edge desktop and 390×844 touch-emulated mobile: rotation, native controls, open/close, interrupted reset, reduced motion, framing, no overflow, zero external HTTP requests/errors. Actual corrupt embedded GLB reaches parser failure and shows poster; no-JS poster also tested.
- `inventory.json` identifies exact payload bytes/SHA-256. `delivery-check.json` verifies required files and ZIP readback. The inventory excludes itself and packaging envelopes to avoid circular hashing. Folder-local Git attributes preserve bytes across checkout.

## Visual acceptance and limits
Actual mobile closed, desktop open, and rear-open captures inspected. All three lakes are visible at mobile size; ochre ridges remain low; interior is visibly hollow. Front-open projection can make the lid seem suspended; the rear view shows hinge-area connections and terrain moving with the lid, backed by attachment overlap tests. Small hardware details remain simplified. The body reads as muted brown stone/clay (and can suggest wood), with shallow rectangular facets rather than convincing fractured volcanic rock. Lakes are flat decorative inlays, not realistic water. Ridges are angular and textures soft at mobile size. No photoreal equivalence, geographically accurate terrain, continuous collision guarantee, manufacturing certification or physical-phone performance is claimed.

`initial/desktop-before-visibility-correction.png` preserves the earlier view before the prior attempt lowered the foreground ridge to expose the lakes. No failing model assertion occurred in this recovery; the deliberate missing-lake negative control was rejected. `lane-output.txt` preserves the prior optional Codex 401 failure: no Codex implementation was accepted. User waived per-asset human review; this is a technically verified v1, not an assertion of human visual approval.

## Reproduce
Blender 5.2.1, Python with Pillow/numpy/Playwright, installed Edge, and Node.js with package.json pins. Build uses local node_modules or sibling iceland-pilot dependencies (not runtime downloads); `npm install` inside this folder restores local build dependencies if needed. No dependencies or .blend1 backups are packaged.

1. Optional regeneration: `python maps.py`, then Blender `--background --factory-startup --python-exit-code 1 --python author.py`. This overwrites source edits; save manual variants separately.
2. `python verify_all.py` rebuilds HTML and runs saved-source, parity, desktop/mobile and theme checks. Blender executable is explicit in the wrapper; adapt for another installation.
3. `node tests.mjs` runs choreography checks; `python review_rear.py` captures the rear view.
4. `python package_delivery.py` recreates SHA-256 inventory, ZIP and delivery check.
