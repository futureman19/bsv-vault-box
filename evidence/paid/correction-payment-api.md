# Correction pass 1: payment API migration (verified payment scope)

- `new Engine(journal, {wallet, transport, paymentObserver, paymentRegistry, hooks})`; `createDemo(file, options)` forwards both payment options. Engine does not close externally supplied registry; factory closes it once all engines close.
- `new ReceiptRegistry('absolute/shared.sqlite')` from `launch/paid/receipt-registry.js`. All production integration factories MUST share ONE durable file across invoice journals/processes. No memory/live fallback. `Payment.configure(engine, invoice, {registry})` can install it, or inject `paymentRegistry` in Engine constructor. Invoice fields unchanged. Immutable binding includes every existing invoice field. Runtime registry UUID and persistent journal owner are bound in PAYMENT_CONFIG; reconnect same file on restart.
- Offline-fixture only: configure installs fixture-only registry tables in the existing Journal DB. This isolation is explicitly simulation-only. Shared external registry can also test cross-journal allocation. Unique `(network,address)`, globally unique invoice ID, unique `(network,outpoint)` attribution; same invoice cannot be configured by another journal owner. Allocation/attribution commits before journal events: crashes retain allocations forever, no release/reassignment API.
- Attach observer BEFORE paid Reserve: initial authoritative address history must be empty (including unconfirmed tx rows). `engine.paymentObserver = receiptFeed('none', clock).observer` is sufficient for fixtures. Reserve performs a new observation internally, persists it, then gates reservation. Historical payments cannot be carried into a reservation. A used address gets durable PAYMENT_ADDRESS_USED. No observer gets durable PAYMENT_UNAVAILABLE. Do not poll a paid feed before Reserve.
- `Payment.poll(engine, observer)` remembers observer. Every invocation now appends a journal event, even identical observations (update dedup/event-count assertions). Transfer reads again before preparing and again after signing immediately before ATTEMPT; resumed PREPARED also reads both times. Factory restarts MUST reattach `paymentObserver` AND the shared `paymentRegistry`; persisted qualification is not enough. No fresh reads or resend after ATTEMPT: INTERRUPTED_SEND hold.
- `ConfirmedReceiptObserver({transport: new HttpTransport({baseUrl: explicitURL, chain: 'testnet'|'mainnet'|'regtest', canary: true /* mainnet HttpTransport requires this */, fetchImpl}), network: 'testnet'|'mainnet'|'offline-fixture', clock, maxTransactions})`. No default URL and only GET. Matching RPC chains are test/main/regtest. Invoice live network MUST equal persisted `state.policy.network`; fixture absent policy.network defaults offline-fixture. Parent's policy/real custody integration remains required for live engine creation.
- Available observations now include `historyTxids` (complete deduplicated bounded history IDs, including unconfirmed), along with prior fields. Every confirmed receipt must belong to history. Height=0 rows are skipped as waiting, not unavailable; disappearance of previously accepted confirmed receipt still holds FINALITY_LOST. Inconsistent/unavailable evidence remains durable hold.
- No live HTTP, keys, node, funds, broadcast, or installed wallet tested. Indexer is trusted for complete history/active chain; not SPV. External registry and invoice DB backups must be coordinated operationally; orphan allocations intentionally require manual reconciliation, never automatic reuse.
